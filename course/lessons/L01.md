# What does a link carry?

## Do this now
Before you paste a link into a DM to a parent, read it to the end and make sure it has a tag.

## The lesson
This is the link that goes with every LumeBook Facebook post (`shared/facts.json`, the field `facebook_link`):

`https://lumebook.com/IL/he?utm_source=facebook&utm_medium=social`

It looks like one line, but it has two parts, and they do completely different things.

**The part before the question mark** says which page to open:
- `lumebook.com` is the site.
- `/IL/he` is the Hebrew home page. `/IL/he/books/41` is the page of the book "Bye Bye Pacifier", `ביי ביי מוצץ` (`research/carousel-audit/data/books.json`).

**The part after the question mark** doesn't change the page at all. The parent sees exactly the same page with it or without it. It is information the link carries for the store:
- `?` says: information starts here, not an address.
- `utm_source=facebook` is a pair of a name and a value: the name is `utm_source`, the value is `facebook`.
- `&` joins one pair to the next.

These pairs are the tags. They answer one question: where did this visitor come from?

**What the store does with them.** When a visitor comes in through a tagged link, the store's code saves the tags. At the end of the book builder, when the book is created, the code sends them along with the order (`research/creator-content-conversion/report.md`, line 514). That's how an order knows where the person who started it came from.

A link without the part after the question mark brings the parent to the same page, but their order arrives with no mark at all. It looks like any other order.

**Instagram adds its own tag too.** The link in the @lumebook.il bio opens with `utm_source=ig&utm_medium=social&utm_content=link_in_bio`, and Instagram adds it by itself (`research/cro-crm/audit.md`, step 0). In a DM nobody adds anything: what you paste is what gets sent.

**The check, five seconds:** look at the end of the link. Is there a `?` followed by `utm_`? You can send it. No? Don't send it until there is.

## Example
Same book, two links:

- `https://lumebook.com/IL/he/books/41`
- `https://lumebook.com/IL/he/books/41?utm_source=instagram&utm_medium=social&utm_campaign=car-pacifier-weaning&utm_content=dm-20261102`

A parent who clicks either one sees the same "Bye Bye Pacifier" page. Only the second one leaves a mark on the order: came from Instagram, from a LumeBook post, from the pacifier carousel, from a DM sent on 2 Nov 2026.

## Common mistake
"The store doesn't record where a buyer came from at all." That's what the marketing tab of the store admin itself says (`docs/lumebook-sales-data-decisions-2026-10-12.md`, section 7). But the store's code does send the tags with every book created. What's missing is a screen that shows them, not the recording. So every tag sent today will count when that screen arrives, and every order without a tag will never count.

## What the numbers can't prove
A tag proves which link the parent came in through, not why they bought. And an order without a tag doesn't prove it didn't come from your work.

## Terms
- **URL (web address)**: the line that leads to a page. The part before the question mark decides which page opens.
- **Tag (UTM)**: a pair of a name and a value after the question mark, for example `utm_source=instagram`. It doesn't change the page, it only tells the store where the visitor came from.
