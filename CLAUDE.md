## How components stay connected

```
python3 tools/lumebook.py status     # what changed, what it affects, open to-dos, consistency warnings
python3 tools/lumebook.py ripple     # same + rebuild safe local pages, sync brand copies, queue the rest
python3 tools/lumebook.py check      # registry, brand copies, offer wording, לומיבוק, em dashes, old paths
python3 tools/lumebook.py ack ID --published   # after republishing an artifact
python3 tools/lumebook.py map        # the dependency graph
python3 tools/lumebook.py build ID   # run one component's build
python3 tools/lumebook.py deploy ID  # Vercel deploy (dashboard)
python3 tools/lumebook.py serve      # one local server for the whole folder: http://localhost:8780/ (runs as a login item, see below)
```

## Design system

- Every internal page uses `shared/design/lumebook.css`: builds inline it with `design.head()`; the dashboard links synced copies (`design.copies`, kept equal by `sync`). Change the CSS, then `ripple` rebuilds the pages and lists artifacts to republish; regenerate the Design System artifact with `build_ds_artifact.py`.
- Style page-specific rules with tokens only (`--bg --surface --text --tint --accent ...`), use `lb-` components first, keep 390px phone width working, Hebrew pages RTL. Light and dark (Yarin, 16 Nov 2026: "add dark mode everywhere, use apple's dark mode ui principles"; replaces white only of 05 Nov): every page follows the system appearance (macOS, iOS, Auto) with no switch, no boot script and no `data-theme`, as Apple's HIG says ("Avoid offering an app-specific appearance setting"). The dark tokens are the same names in the "dark mode" block of `lumebook.css`, right after `:root`, inside `@media (prefers-color-scheme: dark) { :root:where(:not([data-appearance])) {...} }`; a dark-only page rule uses that same guard. Apple's rules there: a near-black base ground (`--bg` #000) with brighter elevated layers (card `--surface` #1C1C1C, insets and sheets lighter, floating glass lightest), brighter colour variants (violet text #A88BFF), 4.5:1 or more for every text token on every surface. Never hard-code a colour in page CSS: use tokens, including the ones added for dark mode: `--tint-solid`, `--success-solid`, `--warning-solid`, `--danger-solid`, `--info-solid`, `--accent-solid`, `--kid-solid`, `--expert-solid`, `--neutral-solid` for fills under white text (plain `--tint`, `--danger`... are text colours, too light under white text in dark), `--ink-fill` / `--on-ink-fill` for an ink pill, badge, toast or tooltip (never `background: var(--text); color: var(--bg)`, which turns into a white pill in dark), `--raised` (a chosen segment or tab), `--raised-a`, `--hover-a`, `--press-a`, `--hi`, `--hi-2`, `--hi-glow`, `--sheet`, `--window-frame`, `--well`, `--well-2`, `--veil` (the lit pieces of the glass), and `rgba(var(--shade), a)` for shadows, `rgba(var(--ink-line), a)` for hairlines. `design.head()` adds the `color-scheme` and `theme-color` metas. A page that draws its own appearance sets `data-appearance` on `html` (only the store mock).
