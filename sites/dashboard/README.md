# Lumebook dashboard

HQ: the LumeBook front door. A live home of numbers, every tool in the project nav's side bar, the course and a few views.

- `lumebook-dashboard.html` – the page. Published as a claude.ai artifact (live signups, saved ticks) and, read-only, on Vercel. It is HQ (Yarin, 5 Nov 2026: "this is the HQ from now on"). Since 5 Nov 2026 its navigation is the project nav that every internal page shares (since 6 Nov 2026 a full-height side bar with no top bar or path row) (`design/nav.js`, the synced copy of `shared/design/nav.js`): the logo goes home (`#home`, the default view since 8 Nov 2026), and the side bar on the right lists "בית" and every tool. The other views (Course, Overview, Signups...) open from their cubes or the side bar. HQ tells the nav its view with `LBNav.setCurrent` and its layout with `LBNav.setLayout` (every `renderTools`), so the side bar follows edit mode. The grid shows every tool as a cube with its own icon and a one-line description, one topic under the other (each topic: colour, icon, description). A cube opens the version that fits where HQ is open: the local page on the project server, the artifact inside claude.ai, the artifact or site on Vercel; a small button on the cube opens the other version. Off claude.ai every link opens in the same tab; claude.ai always opens a link from an artifact in a new tab.

- **Edit mode** (the "עריכה" button): drag cubes within or between topics, drag topics by their handle, click a cube to change its name, description, icon, topic and links (an HQ view, a local path, an artifact, a site), add or delete tools and topics, change a topic's colour, and "איפוס" back to the built-in list. Dragging uses SortableJS 1.15.2 from cdnjs, loaded when edit mode opens.
- **Where the layout is saved:** on the project server `sites/dashboard/hq-layout.json` (GET/PUT `/api/hq/layout` in `tools/lumebook.py`, tracked in git); inside the artifact the database document `hq/layout`; the Vercel copy reads the `hq-layout.json` that `build_site.py` copies and cannot edit. The two saved layouts are separate: ask Claude to copy one to the other (ArtifactData `set hq/layout` from the file, or the document into the file). `{"default": true}` means reset: follow the built-in list.
- **Styles and icons come from the design system** (5 Nov 2026): the grid, edit mode and editor are `lb-filters`, `lb-topics`/`lb-topic`/`lb-cube`, `lb-drag`, `lb-cube-add`, `lb-form`, `lb-icon-picker`, `lb-color-picker`, `lb-app no-sidebar` and `lb-home` in `shared/design/lumebook.css` (Launcher, LauncherEdit, Form cards in the Design System artifact); the page keeps no CSS of its own for them. Icons are `shared/design/icons.json`, linked here as the synced `design/icons.js` (`window.LB_ICONS`); its names are stable because saved layouts store them.
- **The built-in list** is `shared/design/hq-tools.json` (moved out of the page script on 5 Nov 2026, when the project nav started showing it on every page); the page reads it through `design/nav.js`, with the shared rules `toolId`, `defaultLayout`, `mergeLayout` and `toolLinks` (`window.LBNav`). Without `design/nav.js` the grid says so instead of drawing. A tool added there later shows up in a saved layout too (in its topic) unless Yarin deleted it (`removed`); changes to an existing built-in tool show only where the layout was never edited or was reset.
- `course/` – the course: lessons in order with quizzes Claude grades, projects Claude checks, tasks with checklists, weekly numbers, link maker, glossary. How it saves and how to test it: `course/README.md`. It replaced the canvas work board on 31 Oct 2026 (now in `_to-delete/sites/dashboard/board/`).
- `refresh.py` – builds `out/snapshot.json` from the project folder, the live sites, public Instagram counts, the ambassador Sheet export and, under `home`, every home number (`home_stats.py`), plus whether each local tool answered.
- `home_stats.py` – the home's numbers and attention list (see above); `python3 home_stats.py` prints them, `social` refreshes the Postiz numbers, `sheet RAW` saves a cleaned Sheet export.
- `build_site.py` – embeds the snapshot into the page for the static Vercel copy (`site/lumebook-dashboard/`) and copies the course files. Tasks, quiz answers and numbers saved in the artifact are never exported into it.

- **Research pages on Vercel** (Yarin, 5 Nov 2026): `build_site.py` also copies five research pages to `/research/<slug>/` on the Vercel site, read-only and `noindex`: competitor teardown, kids content lab, carousel research, carousel playbook, parent communities. The list is every `shared/facts.json` artifact with a `web` address under `/research/`; the page copied is its `lumebook.json` `publish.file`, with the files it links by a relative path (carousel research: `img2/`). On the Vercel copy the research library and the tool cubes open these copies (`artifact.web`, `WEB_COPY` in the page); in claude.ai and on the project server nothing changes. Pages with internal sales figures or personal data never get a `web` address: the reels research and reels system, the creator-content report, CRO/CRM, the sales readout, the carousel audit and the creator map. The dashboard watches the five pages, so the nightly job redeploys after one of them is rebuilt.

The nightly commit job (`tools/nightly_commit.py`, 00:00) runs refresh (Postiz included), then `python3 tools/lumebook.py deploy dashboard` (build, then `npx vercel deploy --prod --yes` from `site/lumebook-dashboard`) when a watched file changed since the last deploy.
