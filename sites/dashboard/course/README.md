# The course (the dashboard's default view)

The LumeBook pipeline course, since 31 Oct 2026. In English, left to right inside the Hebrew dashboard (Yarin, later on 31 Oct: "i need it to be like a course and a way for you to check my answers, i want the course fully in english"). It opens on the Course tab: lessons in order by week, each on its own page, a Continue button, and the projects. Claude grades the written quiz answer and the project hand-ins in the page. Tasks are still there: Yarin adds them by hand and picks a type; each type carries a checklist that fades as tasks of that type get done, and shows the next lesson of that type. Plan and decisions: `course/discovery.md` and `course/curriculum.md` (both approved by Yarin, 31 Oct 2026; the change is noted under the curriculum's Status).

| File | What it is |
|---|---|
| `course.js` | The view (no framework). Loaded by `../lumebook-dashboard.html` after the dashboard script. Tabs: Course (home, lesson pages, project pages), Tasks, Sales, Numbers, Links, Glossary |
| `course.css` | Its styles, on the design system tokens and `lb-` components. White and black modes, 390px |
| `course-data.js` | Generated by `python3 course/build.py` from `course/lessons.json`, `course/lessons/*.md` and `research/carousel-audit/data/books.json`. Do not edit |
| `dev/mock-artifact.js` | Test harness for the artifact-database path, with a stand-in for Claude's check. Not deployed |

## Where it saves

| Where the page runs | Saved in | Shown as |
|---|---|---|
| The artifact (claude.ai), with `db` | The artifact database: `course/tasks`, `course/progress`, `course/numbers`, `course/settings`, `course/links`, `course/sales` | "Saved in Claude" |
| The Vercel copy, the local project server, a file | This browser's `localStorage`, key `lb-course:v1` | "Saved on this device only" |

- Items sit in nested maps keyed by id (`course/tasks` → `items.<id>`) and are written with `update()`, which merges nested objects, so the Mac and the phone can change different tasks without overwriting each other. A removed task gets `deleted: true`; its key is never removed. One write at a time per document; a failed write is retried and the header says so; a refused write makes the view read-only.
- Never touches `snapshot`, `history`, `tracker` or the old board's `boards/`.
- `build_site.py` ships only the lesson content to Vercel. Lesson files never contain LumeBook sales figures for that reason (`course/curriculum.md` §0).

## Claude's check

- The page asks Claude through the artifact's `sample` capability, on Yarin's own Claude account; the first call asks Yarin to allow it. On "Submit for Claude's check" the written answer goes to Claude with the lesson's teaching text and the question's model answer (the `> ` lines under `### Question 3 · open`), and comes back as a verdict on the curriculum's §10 scale: ✓ correct (1), ↑ above the standard (1), ~ partial (0.5), ✗ wrong (0), with feedback and the missing points. Stored on the attempt: `course/progress` → `lessons.<id>.tries.<n>.claude`, `open`, `score`.
- A project hand-in goes to Claude with the project's `check` from `course/lessons.json` and, where `attach` says so, Yarin's own saved records (`links`: the tag values and the last 7 days of the link log; `numbers`: the last two saved weeks). Stored in `projects.<id>.checks.<n>`; a ✓ or ↑ without `redo` marks the project done.
- Where Claude cannot run (the Vercel copy, the local server, a viewer who declined, an account without it), the page says so and Yarin grades the written answer themself, as before; hand-ins are saved unchecked. Errors offer "Ask Claude again"; nothing retries by itself.
- Everything Yarin answers stays in `course/progress`, so Claude Code can also read it back (`ArtifactData` list on `course` of https://claude.ai/artifact/R5tEXfKkNKzVYg8CWFh4s6) and go through it with Yarin.

## Rules the view keeps

- Lessons open in course order: a lesson opens once its prerequisites in `course/lessons.json` are passed. Continue goes to the first open lesson not yet passed. A task still shows the next lesson of its type. Reading a lesson never blocks "Done".
- Quiz answers stay sealed until submitted. Peeking is allowed and recorded with the attempt. Score = right set answers + the grade on the written answer (Claude's, or Yarin's own where Claude cannot run); 2 of 3 passes, under that the lesson says redo and the lessons that build on it stay locked. "Try again now" starts a new attempt.
- The checklist fade comes from `course/lessons.json` `fade`, counted by tasks of that type already done: open, then folded, then Yarin writes their own steps first.
- The weekly numbers week runs Sunday to Saturday and cannot be saved without the "what these numbers can't prove" sentence. "Not available yet" is a real answer for tagged clicks and tagged orders.
- The link maker builds `utm_source` (network), `utm_medium` (Yarin's chosen value, `social` by default; `creator` and `paid-social` refused), `utm_campaign` (`car-<topic>`), `utm_content` (`<placement>-<yyyymmdd>`, or `bio`) from `research/cro-crm/measurement.md` §4. Copying logs the link; the log counts messages sent with it. The Links tab also holds a read-only "UTM list" (`utmList()` in course.js): the Instagram and Facebook tag strings that count as Yarin's, the media that never do, and the pre-send check (1 Nov 2026; same content as `docs/utm-list-ig-fb.md`).

## Rebuilding and testing

```
python3 course/build.py                    # lesson data (ripple runs it when course/ changes)
python3 sites/dashboard/build_site.py      # static copy in site/lumebook-dashboard/
```

The harness iframe lays out at 980px, so check phone width on the local preview, not in the harness. ## Sales tab (1 Nov 2026)

Yarin's number: paid orders whose `utm_medium` is exactly their tag value (default `social`), counted from an export Yossi sends (`research/cro-crm/yossi-messages-2026-10-31.md`, message 1). Paste a spreadsheet copy, a CSV or JSON under "Add Yossi's export"; the page guesses which column is which (first and last touch, a status column, amounts in agorot) and Yarin corrects it before adding. Shows orders, amount, 25% of that amount (price-only or with shipping is still open with Yossi), the share of paid orders with any tag, and the orders by link. Orders that match only on the other touch, or only on an October value (`dm`, `bio`, `story`), are flagged and not counted.

Saved in `course/sales`: `orders.<key>` (only orders that carry the tag or an October value, so re-pasting overlapping exports never double counts), `days.<date>` (every paid order per day; an import replaces each day it covers), `imports.<id>`. A later export that lists an order as refunded or cancelled removes it. The Numbers tab pre-fills "Tagged orders" when exports cover all 7 days of the week. Not checked: the real export format (the columns are not known until Yossi sends one), and the artifact-database path (only the local-storage path was tested; run the mock harness before republishing).
