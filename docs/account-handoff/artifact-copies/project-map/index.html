LumeBook project map

One repo, 16 components registered in lumebook.json. tools/lumebook.py reads that registry to work out what a change touches. The pictures below show what feeds what, the shared brand and CSS layer, the loop that keeps copies honest, and what runs on its own each day.

What feeds what

Almost every arrow ends at the dashboard: it is the only component that reads all the others. The two dashed arrows into the pipeline are the fragile ones, because nothing rebuilds them. When the playbook or the carousel research changes, someone has to update hook-bank.md or the code words in carousel_lib.py by hand.

The shared layer

Brand files and the stylesheet live once, in shared/. Anything that deploys on its own folder needs a physical copy, so sync writes one. Pages with a build step inline lumebook.css instead, so they never drift.

How a change ripples

Local work is automatic; anything published as an artifact is not. ripple can rebuild the HTML, but the claude.ai copy stays stale until it is republished and acknowledged.

  • python3 tools/lumebook.py status: what changed and what it affects, no writes
  • python3 tools/lumebook.py ripple: the loop above
  • python3 tools/lumebook.py check: offer wording, brand spelling, em dashes, old paths

What runs each day

Two scheduled tasks. The morning one only reads and publishes the dashboard. The evening one only writes drafts; nothing costs money until you pick an option.
