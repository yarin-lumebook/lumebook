# Creator map source

`lumebook-creator-map.html` in the folder above is generated. Edit the files here, then rebuild:

```bash
python3 src/build2.py
```

- `template.html`: the page (styles, layout, outreach tool, dashboard script) with `__DATA__`-style placeholders.
- `build2.py`: fills the placeholders with the creator data and writes the map. It also turns long dashes into commas or hyphens.
- `build2.py` also reads the offer from `../../../shared/facts.json` (the 25% allocation, the split example, the paid-hold list), so the messages and the offer check never keep their own copy of the numbers. Change the offer there, then rebuild.
- `enrich.py`: adds waves, opener lines and the "moment" for each creator.
- `C_all.json`: the 347 verified creators (204 from 3 Oct, 100 from 11 Oct, 61 under-5K removed on 12 Oct, 100 added on 18 Oct, 2 added by hand on 20 Oct, 1 on 21 Oct, 1 on 22 Oct). `contacts.json`: the emails and phone numbers each creator publishes themselves.
- Since 20 Oct 2026 the free text in `C_all.json` is Hebrew, like the rest of the map: `role`, `topics`, `concept`, `risk`, `ages` (״2 עד 8״), `loc`, `contact` and the `roles` list. The English is in git history. `arch`, `prac` and `conflict` stay English because they are keys that `template.html` maps to Hebrew labels. The `research/data*.py` files are still English, so a new research pass should write its new rows in Hebrew, following `hebrew-rules.md`. `enrich.py` reads both languages and gives each of the 343 creators the same moment and wave as before.
- `kids.json`: how many kids each creator has and their genders (`n` total, `b` boys, `g` girls, `names` in Hebrew letters, `names_en` when the bio writes them only in English and `names` is the transliteration, `note`, `src`), only where the public bio says so. Nothing is guessed from names. Fill it in for every new creator.
- `test_kids_names.mjs`: checks the built map: every suggested message names the kids at most once (later mentions say הילדים, הילדה and so on) and no name is left in English. Run `node src/test_kids_names.mjs` after a build; `--show handle1,handle2` prints those creators' messages.
- `hebrew-rules.md`: the Hebrew rules the messages follow (agreement, definite article, construct chains, prepositions, punctuation). The map checks the checkable ones.
- `research/`: the scripts and hand-written records that produced `C_all.json` (first pass, second pass, merge rules, edge cases and exclusions).
- Third pass (11 Oct 2026): `research/data3.py` holds the 100 added creators, `research/pass3_raw.json` the numbers and bios as read that day, and `research/merge3.py` appends them to `C_all.json`, `kids.json` and `contacts.json`. To add more creators later, write a new data file in the same shape and run a copy of `merge3.py`.
- Fourth pass (18 Oct 2026): `research/data4.py`, `research/pass4_raw.json` and `research/merge4.py` (same shape; it also appends the rows to the CSV the dashboard counts). Found by pulling Instagram's similar-accounts list for all 304 known handles (about 6,300 new accounts), screening about 5,800 by the follower count and bio in each profile page's description, then a second hop from the first 91 picks. Every one of the 100 has 5,000 to 50,000 followers and a reel since July. A profile's Instagram id (pk) is the safe duplicate check: `by_shanina` turned out to be the renamed `shanina_advent.learn`.
- Weekly passes (since 24 Oct 2026): every Saturday at 21:00 the scheduled task `lumebook-creator-map-weekly` adds up to 100 more, one pass number per week (6 on 24 Oct). Method, scripts and rules: `research/weekly/README.md`. Its rows go through `research/merge_pass.py <N>` (one merge for every later pass, written for the Hebrew rows), which also stores each new creator's Instagram `pk` and `added_on`; `build2.py` shows each week as its own batch ("סבב שבועי N" in the filters). `research/weekly/reviewed.json` lists every account a weekly run already reviewed, so the next runs skip them for 90 days. On 24 Oct the test run found `art_by_shanina`: the same account as `shanina_advent.learn` (renamed again after `by_shanina`), so the map's row was renamed to `art_by_shanina` that day (C_all.json, contacts.json, the CSV; it had no outreach record) and given its pk.
- Admission bar (Yarin, 24 Oct 2026): a new creator joins only with 5,000 to 50,000 followers, median views 2,000+, 0.4+ views per follower, 10+ likes and 1+ comment per 1,000 views (`shared/facts.json` `creators.admission`, applied by `research/weekly/gate.py` in `weekly.py check` and `merge_pass.py`). Creators already in the map are never removed or changed by it.
- "הוספת יוצרים" button (24 Oct 2026, top bar on every page): Yarin pastes handles or Instagram links. One already in the map opens at once; new ones go into a queue saved in `state/settings.json` (`main.addq`). The page cannot read Instagram, so the Saturday run reads the queue (`research/weekly/weekly.py queue`), checks each handle against the admission bar, adds those that pass first, and writes what happened to each into `research/weekly/requests.json` (`weekly.py requests`), which `build2.py` builds into the form: added, the reason it did not pass, or still waiting.
- Performance on each card (24 Oct 2026): followers, median views and views per follower for every creator; likes and comments per 1,000 views and buying questions per 100 comments first for the 134 creators in `research/creator-content-conversion/round2/creators_kpi.csv` (their 12 most recent posts, measured 14 Oct 2026; `build2.py` reads it into `kpi`), and since 24 Oct 2026 for every creator by the refresh (every night at 00:00 since 15 Nov 2026; `refresh/README.md`: `refresh/latest.json` `kpi`, a fresh number replaces the 14 Oct one field by field); sales through the link when typed on the card. The six boxes show on every card (since 5 Nov 2026 the design system's `lb-metrics sm` tiles, Yarin: "move them"); a number we do not have says "אין נתונים" (`is-empty`). Each number is rated against the rest of the map (the measured 134 for the last three): top third green (`is-ok`, number and label in green) with an arrow up, bottom third red (`is-bad`) with an arrow down, middle third neutral with a flat line (`lb-metric-mark`); the hover text gives the exact share. After a weekly refresh the followers and views show the change since the research (`f0`, `med0`).
- Follow-ups page `#followups` (24 Oct 2026): everyone whose follow-up is due, as a stack of full cards like the reminders, the most recently due on top. It replaces the "פולואפ לשליחה" link in the sidebar (`#c-due` opens it). The strip above each card picks the channel: another one than the first message when the creator publishes one (WhatsApp, then email, then Instagram), shown as the "פולואפ בערוץ אחר" message, which carries the first message since the creator never saw it there. "העתקה ופתיחת הצ׳אט" copies the text and opens `ig.me/m/<handle>`; "שלחתי ✓" records the follow-up (with its channel, `fuch`) in one tap, without the note popup; "בלי פולואפ" moves the creator to No reply.
- Icons and motion (24 Oct 2026): every action button carries an icon from `ICON` in `template.html` (channel buttons use the channel's own icon, `CHI`; since 5 Nov 2026 every icon comes from the shared set, see the design system note below), the six performance tiles have one per metric (`PIC`), empty pages show a check. Motion is short and functional: pages rise in on a route change, the drawer slides in, the note popup and menus pop, details open with a fade, buttons press, copied and done marks pop, counts bump when they change, the saving dot breathes. Timings are the `--mo-*` custom properties; everything is off under reduced motion.
- Books (30 Oct 2026): the sidebar tab "ספרים שנוצרו" (`#books`) is an editable table, one row per book we made: creator handle (picks from the map), child, book, created and sent dates, Drive folder, note. Rows live in `settings/main` `books` (`id, h, qty, arrived, up, child, title, on, sent, note, dr`). The Drive folder belongs to the creator (`dr` in `state/outreach.json`, so it is the same in every one of their rows and on their card); `dr` on a row is only used for a handle that is not in the map. The card shows how many books a creator has and links to the table; the list filter "ספרים ותוכן" and the sort by book count read the same rows. A card in process also has the Drive folder field and an "פתיחת התיקייה" button.
- Books tab, posts and cubes (5 Nov 2026): the summary sentence is now six number cubes, the design system's `lb-metrics` / `lb-metric` tiles (books and for how many creators; arrived and creators with content up, each with a progress bar and the count still waiting in amber; the linked posts' total views, likes and comments with the change since the previous reading). The "פוסט ודרייב" column holds the post link and the Drive folder one above the other (`post` on the row; pasting a post link ticks "תוכן עלה"), and under the creator's handle three cubes show that post's views, likes and comments, the change since the last reading, and the posted and checked dates. Colours (Yarin, same day: "color code and make everything bigger and clearer"): books, views, likes and comments have their own hue from `shared/design/categories.json` set `books-metrics` (passed by `build2.py` as `BKCAT`, used as `lb-cat-N`), the same in the summary and on every row; arrived and content up are status, so green when done and amber (`lb-wait`, `lb-chip warning`) for a book on the way or content still missing after the book arrived. The pieces all live in `shared/design/lumebook.css` since 5 Nov 2026 (`lb-metrics` with `sm` per post, `lb-bar is-progress`, `lb-wait`, `lb-toggle`, `lb-linkfield`, `lb-table is-roomy`, `lb-btn quiet`) and in the Design System artifact (Metric, Toggle, LinkField); only column widths stay in `template.html`. The numbers come from `state/posts.json`, written every night at 00:00 by part A of the scheduled task `lumebook-creator-cards-daily` (09:00 `lumebook-creator-posts-daily` until 15 Nov 2026) through `posts/` (method in `posts/README.md`); the page fetches them from the project server.
- Unfit tab (30 Oct 2026): declined creators who fail the admission bar (`ADM` from `shared/facts.json`) show under "לא מתאימים" instead of "סירבו" (`unfitOf`, in `bkOf`).
- Books tab, "בפרסום ממומן" column (18 Nov 2026, Yarin: "i need a way to tick if i added them to paid"): one switch per book row (`paid` on the row in `SET.books`, saved with the other row fields), green "נוסף" when ticked, "עוד לא" otherwise. A hand tick only; nothing reads it yet.
- Dates show as `dd / mm / yyyy` (`dayLabel`, `isoDL`, `dL`), isolated with LRI/PDI so RTL text keeps their order. Since 5 Nov 2026 the static text uses `<bdi dir="ltr">03 / 10 / 2026</bdi>`, `build2.py` rewrites any long Hebrew date in the data (״20 באוקטובר 2026״ in refresh flags and research notes) the same way, and the old `chk` field is gone.
- Design system pass (5 Nov 2026, Yarin: "add every change we ever made to the design system, only the most updated versions"): the page follows every current rule in `shared/design/lumebook.css` and the project CLAUDE.md. White only, no side stripes, tokens only (no rgba or hex in the page CSS; `.oc` frame and shadow are `color-mix` of `--text`), Assistant (`--font-2`) on labels, counts, legends and captions, violet only for things you click (the books tab handle link was gold), the toast in `lb-toast` colours (ink ground, white text). Icons: the map's own 20-grid set is gone. `ICN` in `template.html` maps the page's short names (`cal`, `insta`, `ext`...) to names in `shared/design/icons.json` (24 grid, stroke 2), and `build2.py` passes the set as `LBI`, turns `__ICON:name__` in the static HTML into `design.icon()`, and stops the build if a mapped name is missing. The 30 icons the map needed were added to the set that day (`map`, `gift`, `whatsapp`, `instagram`, `eye`, `heart`, `rate-up` and so on). No emoji or arrow characters as markers: ⏰ is the clock icon, ↗ is `open-out`. Shared components replace page copies: `lb-crumbs` (top bar), `lb-kbd`, `lb-savestate` (`is-wait`, `is-error`, `is-local`), `lb-popover` (the status menu, fixed to the page), `lb-flash` (a card the page jumps to), `lb-kv stack` (database details), `lb-pair` was/now (the 20% migration diff), `lb-clamp-2`, `lb-table mid` and `top`, and the card's six numbers are `lb-metrics sm` with `lb-metric-mark`. Page CSS keeps only what is the map's own (card zones, reminders stack, filter panel, motion).

- Experts badge (06 Nov 2026, Yarin): every creator who is a professional in the child and parenting field carries a solid ink pill with a cap icon and the field, next to the handle on the card (the avatar gets a small ink mark of the same icon) and in the database row, and one press of "מומחים בלבד" in the toolbar of the contacts pages and the database shows only them (the count on the button is how many there are in that list; the same filter is in the filter popup under "מומחים", with a choice by field and the count for each). The eleven fields are the eight Yarin named plus three he added the same day: `guide` הדרכת הורים וייעוץ משפחתי, `sleep` ייעוץ שינה, `potty` ליווי גמילה מחיתולים, `slp` קלינאות תקשורת, `ot` ריפוי בעיסוק, `psy` פסיכולוגיית ילדים (also child psychotherapists), `biblio` ביבליותרפיה, `classes` חוגים וסדנאות לגיל הרך, `arts` טיפול רגשי ובאמנות (art therapists and emotional therapists of children), `physio` פיזיותרפיה התפתחותית, `med` רפואה וסיעוד (doctors and nurses); named as fields, not as people, so they fit women and men alike. `experts.py` decides: it matches patterns over each creator's bio line (`role`), counts the research archetype "Parent guide / coach" as `guide`, and `build2.py` writes the result as `xp` on every creator, so the creators the Saturday run adds are tagged without any step. `experts.json` is the hand list and always wins (`add` / `drop` per handle, `why` for the reason); fix a wrong badge there, not in the patterns. `python3 src/experts.py` prints who got which field. Not in the list, so no badge: nutritionists and kindergarten teachers (unless the bio also says parent guidance); add one to `experts.json` if Yarin wants them. Nobody is a `biblio` yet. This is not the outreach track "אנשי מקצוע" (`pro`, the message set and the avatar hue), which stays as it was.

Where the map runs, and where its data lives (since 20 Oct 2026): open it on the project server, `http://localhost:8780/creators/creator-research/lumebook-creator-map.html` (`python3 tools/lumebook.py serve`). Statuses, notes, reminders, settings and the voice are saved by the server into `creators/creator-research/state/` (`outreach.json`, `settings.json`, `voice.json`, `log.json`; private, not in git; `state/export-2026-10-20/` is the copy taken from the artifact database that day). The page detects the server and uses `/api/creator-map/state` and `/api/creator-map/doc`; elsewhere it behaves as before (artifact database, or browser-only in a preview). The old artifact https://claude.ai/artifact/MPuqcaCXXF5CGQiDMaDpbB belongs to the previous Claude account, still holds the 20 Oct 2026 database and is no longer updated. On 05 Nov 2026 Yarin asked for a copy on this account: https://claude.ai/artifact/DCJ2ZT1Y4K8MrcH5bot2Hj (private), published from `lumebook-creator-map.html` with `state/posts.json` as a file and its database filled from `state/` (`outreach` 380 documents, `settings/main`, `voice/main`, `log/<handle>/events` 391). It is a snapshot, not a mirror: the project server stays the master, edits made in the artifact never reach `state/`, and edits made on the server never reach the artifact. The status pill carries the status colour (`st-*`); colour otherwise only for the track avatar and the green/red tile ratings. No coloured stripe on the card edge (Yarin removed it, 1 Nov 2026). Cards are set apart by a 2px frame and a deeper shadow than other `lb-card`s (`--oc-edge`, `--oc-edge-hi`, `--oc-shadow` on `.oc`). Zone labels are `.oeb`. In the drawer the footer zones become framed boxes.
